# klc-light Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An Omarchy-native per-key RGB editor for the MSI GS76 SteelSeries KLC keyboard (`1038:113a`), with an on-screen preview, one profile per Omarchy theme, and a `klc-light apply` command for the theme hooks.

**Architecture:** One C++/Qt Quick binary built with qmake6 following the `omarchy-app` skill (`~/.claude/skills/omarchy-app/SKILL.md` and `templates.md`). Pure units (Layout, Profile, Effects, Protocol, ThemeProfile, Preview) are tested offline; Protocol output is compared byte for byte to fixtures produced by the user's validated Python tools. Only Device touches hardware, through injectable interfaces.

**Tech Stack:** C++17, Qt 6 (Core, Gui, Qml, Quick, QuickControls2, Test), hidapi-hidraw 0.15 (pkg-config `hidapi-hidraw`), libxkbcommon (pkg-config `xkbcommon`), Python 3 only for the fixture generator.

**Spec:** `docs/superpowers/specs/2026-10-29-klc-light-design.md`

## Global Constraints

- Project root `~/Work/klc-light`; binary, package, `.desktop`, icon and app id are all `klc-light`.
- Follow `omarchy-app`: flat `src/`, `bin/build`, `bin/test` (offscreen), `bin/install` (`makepkg -fsi`), theme accent followed live, `qsTr()` everywhere with `src/i18n/fr.json`, Material Dark, `theme.radius`, `?` shortcut overlay, `Q` quits (asks if unapplied changes).
- USB id `1038:113a`. Feature reports are 524 bytes, output reports 64 bytes; the first byte of each packet is the report id (`0x0e`, `0x0b`, `0x09`), sent as-is with `hid_send_feature_report` / `hid_write`, exactly as `msi_perkeyrgb/hidapi_wrapping.py` does.
- Every send ends with output report `09` + 63 zero bytes.
- Binder commands: `sudo -n /usr/local/bin/msi-kbd-usb bind` and `... unbind`; unbind always runs after bind, even on failure.
- One send per apply, no automatic retry. Lock file `$XDG_RUNTIME_DIR/klc-light.lock`; last-send timestamp `$XDG_RUNTIME_DIR/klc-light.last`; minimum interval 5000 ms; hidraw wait 3000 ms.
- Profile file name `keyboard.klc.json`, `"version": 1`; brightness 1–100, speed 25–400 (percent); at most 16 transitions per effect; at most 6 animated effect slots in v1; one key belongs to one effect.
- Reactive mode is stored and edited but never sent unless the profile has `"reactive": {"enabled": true}` AND the build was started with `--experimental-reactive` (CLI) or the editor's experimental switch; off by default.
- Never write to `~/omarchy`, `/usr/share/omarchy`, or `~/.local/state/omarchy`; profiles are saved only under `~/.config/omarchy/themes/<theme>/`, atomically (write beside, rename).
- No hardware send happens in any automated test; real sends happen only in Task 12, one at a time, after the user agrees.
- Source strings in English; French translation shipped. Comments explain why, in full sentences. Commits short and imperative.

## Review Focus

1. **Rapid theme switching** (`omarchy theme next` twice within 5 s): the second apply must wait for the interval and then send the final theme's lighting, never be dropped — test in Task 8.
2. **Saving a profile for a stock theme** (no `~/.config/omarchy/themes/<name>/` yet): the directory is created holding only `keyboard.klc.json`, not a copy of the theme — test in Task 7.
3. **Hand-edited profile** with an unknown key name, `"version": 2`, a missing field or bad color: rejected with a message naming the field, nothing sent, `apply` exits 1 — test in Task 4.
4. **Keyboard missing or sudo needing a password**: `sudo -n` fails fast, hidraw wait capped at 3 s, the theme hook never blocks longer than about 4 s — test in Task 8.
5. **Colors that do not close a cycle exactly** (odd channel steps, brightness scaling): the closing transition absorbs the rounding so the effect still builds — test in Task 5.

### Task 6: Protocol

**Files:**
- Create: `src/protocol.{h,cpp}`
- Test: slots `protocol*`

**Interfaces:**
- Consumes: `Layout`, `Profile`, `Effects`, `:/presets/aqua.json`.
- Produces:
  - `struct Packet { enum Kind { Feature, Output } kind; QByteArray data; };`
  - `struct BuildResult { QList<Packet> packets; QStringList errors; };`
  - `BuildResult buildPackets(const Profile&, const Layout&, bool allowReactive = false)`
  - `Profile builtinProfile(const QString& name)` — `"ares"` / `"tron"`: the `aqua` key→slot mapping (slot 0 uses the pulse palette, slots 1–5 the waves palette), base static black for aqua's steady keys.
  - `std::optional<Profile> profileFromLegacy(const QString& effectName, const QString& rgbHex)` — `keyboard.effect` name → `builtinProfile`, else `keyboard.rgb` → static base.
- Rules:
  - Key fragment, 12 bytes: `R G B rR rG rB timeLE(2) effectIndex settingsMask 00 hid`; settingsMask `1` steady, `0` effect, `8` reactive (only when allowed and enabled; reactive bytes are zero otherwise).
  - **Static path** (no animated slot): for each region in order alphanum, enter, modifiers, numpad, one feature packet `0e 00 <code> 00` + one fragment for every `regionHids` code in list order (the key's color, else the base color, × brightness) + trailer 14×`00` + `08 39`. All four regions are always sent, so a profile never inherits colors from the previous one. Then output `09`.
  - **Effect path** (≥ 1 animated slot): slots numbered 0..n−1 (base first if animated, then effects in order); regions enter, modifiers → effect packets in the order `4,3,2,1,0,5` filtered to slots < n → regions alphanum, numpad; region packets list only `aquaHids` codes, trailer 16×`00`; each effect packet = the aqua effect packet whose byte 2 equals the slot's origin number, byte 2 set to the slot index, table at `0x02..0x82` (first entry's number = slot index, others = their index), start color at `0x84` (each channel nibble-swapped over two bytes: `0x52` → `20 05`), count at `0x96`, total duration LE at `0x98`; then the aqua 64-byte `09` feature packet; then output `09`.
  - Every packet is 524 bytes (feature) or 64 bytes (output); any other size is an error.
